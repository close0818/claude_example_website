影響

新環境容易「健康但不可用」

Compose 建立空資料庫時，三張資料表可能沒有被建立。`/api/health` 只回靜態 OK，無法證明 schema 可用。

修復方向

以版本化 migration 或逐條 DDL 初始化；任何 schema 錯誤都要讓啟動失敗。另設 readiness 檢查確認 DB 與必要表存在。

證據：internal/db/db.go · Open()

P1 · 借閱併發競態

檢查在交易外，兩筆請求都可能借出同一本書

請求 A
讀到 available
↘
時間交錯
A、B 都完成狀態檢查
↙
請求 B
也讀到 available
目前流程
SELECT book.status // transaction 外 BEGIN INSERT borrow_records UPDATE books SET status='borrowed' COMMIT

狀態更新沒有 `WHERE status='available'` 條件，也沒有檢查 RowsAffected；資料庫沒有唯一約束阻止重複的 active loan。

建議流程
BEGIN UPDATE books SET status='borrowed' WHERE id=? AND status='available' 檢查 RowsAffected = 1 INSERT borrow_records COMMIT

或在交易內 `SELECT ... FOR UPDATE`；加上 active loan 的資料約束，並以併發測試驗證唯一性。

證據：BorrowBook() 中狀態查詢先於 Begin()05 / 08

P1 / P2 · 上線前需補

管理型 API 尚未建立安全邊界

正式環境阻擋
!所有路由無認證/授權 middleware；任何可連線者都能操作館藏與借還。
!CORS 使用 `Access-Control-Allow-Origin: *`，Compose 對外暴露 API 與 MySQL port。
!Compose 以 root 帳號與明文弱密碼連線；應改成最小權限 DB 帳號與環境 secret。
可靠性與 API 語意
!`GetBook` 將所有 SQL 錯誤都回成 404，資料庫故障會被誤報成不存在。
!列表迴圈沒有檢查 `rows.Err()`；讀取中斷可能仍回傳不完整的 200 結果。
!UpdateBook 缺少欄位驗證；status 空值會重設為 available，可能覆寫借閱狀態。

另需限制 CORS 來源、隱藏內部 SQL 錯誤細節、設定 request/DB timeout，並將 HTTP status 與資料庫錯誤正確分類。

證據：handlers.go · CORS / GetBook / UpdateBook / list handlers06 / 08

LRECOMMENDED ROADMAP
08 / 08
先解除上線阻擋，再擴充功能

四步把可編譯推進到可營運

01 · P0Schema / startup：拆分 DDL 或加入正式 migration；初始化錯誤 fail fast；加 DB readiness 與啟動 retry。
02 · P1一致性：借閱狀態更新改成原子條件更新或 row lock；補 active loan 約束；修正歸還冪等性。
03 · P1安全：加入認證/角色授權；CORS allowlist；DB 使用最小權限帳號，憑證從 secret 注入。
04 · P2品質門檻：補 handler + MySQL 整合測試、併發借閱測試；檢查 rows.Err、欄位驗證、分頁與錯誤映射。
建議上線門檻：乾淨資料 volume 可啟動、健康檢查含 DB、核心借還測試通過、未授權請求被拒絕。
後續可依此路線逐項修復並重新驗收08 / 08
